# 重大差异判定规则

## 功能单元基线

按功能映射范本和待审文件。标题、顺序、编号或措辞不同不构成差异，只要功能被等效实现。

| 功能组 | 关键功能单元 | 重大差异示例 |
|---|---|---|
| 发布与项目识别 | 项目/标段、招标范围、资金或预算信息、联系人、获取文件方式 | 无法识别采购对象或响应边界；公告核心信息在正文中无对应口径 |
| 投标程序 | 时间地点、澄清修改、现场踏勘、投标有效期、保证金、递交/撤回 | 缺少投标截止或递交流程；关键时间链无法执行；引用不存在的电子平台流程 |
| 资格与符合性 | 主体资格、资质/许可、人员、业绩、财务、信用、联合体、证明材料 | 缺少资格审查规则或证明材料要求；资格条件与审查表脱节 |
| 投标文件组成 | 商务、技术、报价、授权、承诺、偏离表、签署盖章、目录格式 | 要求提交的关键材料无对应格式或填报位置；附件/表单缺失导致无法响应 |
| 开标与评审 | 开标、资格/符合性审查、评标方法、评分因素、公式、并列处理、推荐规则 | 评审阶段缺失；评分表或公式缺失；分值体系无法落地；否决条件无审查入口 |
| 技术与交付 | 需求范围、数量单位、性能参数、标准、接口、交付、检测验收、偏离处理 | 技术需求正文或关键附件缺失；无验收依据；需求与响应表无法对应 |
| 报价与支付 | 报价范围、币种税率、价格表、限价、评标价、调整机制、支付节点 | 缺报价表或计价口径；价格比较无法执行；报价范围与合同价款范围脱节 |
| 合同文件 | 合同组成、优先顺序、范围、工期、付款、担保、质保、违约、终止、争议 | 合同核心条款整章缺失；通用/专用条款引用断裂；缺少关键风险分配机制 |
| 附件与发布控制 | 清单、图纸、技术附件、合同附件、签署页、编制说明、版本标识 | 正文明确引用但未提供附件；关键占位符未填；文件版本或签署主体无法确认 |

## 状态判定

- `matched`：功能完整，差异仅为编号、位置、措辞或合理项目定制。
- `materially_modified`：功能仍存在，但义务、权利、程序、门槛、计算或风险分配发生实质变化。
- `missing`：经目录、同义词、关键义务词、引用关系和附件复查后，适用功能仍不存在。
- `unlocatable`：可能存在，但因缺页、图片不可读、解析错误、附件不可访问或引用不清无法可靠定位。
- `not_applicable`：基于项目类型、采购制度或用户确认，该范本功能不适用。

## 严重性

### blocker

仅在差异会直接阻止文件可靠发布、投标人形成有效响应、评审实施或合同成立/执行时使用，例如：

- 待审文件无法确定采购对象或投标截止；
- 核心技术需求、工程量清单、报价表、评标办法或合同主体文件整体缺失；
- 正文强制引用的关键附件缺失，且没有等效信息；
- 关键流程前后断裂，无法确定有效投标或中标人的产生方式。

### major

差异不会完全阻止流程，但可能显著改变竞争范围、响应成本、评审结果、价格比较或合同风险，例如：

- 范本中的关键程序保障被删除或改为无法验证的自由裁量；
- 资格、评分、报价或合同功能单元存在实质内容缺口；
- 大量占位符未填，或关键附件、表格和正文不能对应；
- 范本的责任边界被显著改写，但未说明项目原因或补偿机制。

### minor / info

编号、排版、标题、顺序、非关键格式、已有等效条款的措辞差异通常为 `minor` 或 `info`。除非这些差异造成错误引用、提交失败或解释冲突，否则不进入重大问题主清单。

## 降级与排除

以下情况不得仅凭范本差异判为重大：

- 项目特性必然导致的数量、技术参数、工期或交付地点变化；
- 范本明确允许招标人选择、删除或另行约定的可选条款；
- 同一功能被移动、合并或用等效表述实现；
- 范本与项目在地区、采购制度、行业或版本上不完全匹配；
- 只掌握范本目录或摘要，没有回读范本原文；
- 解析工具未识别到内容，但原 PDF 页面或附件尚未核实。

上述情况应判为 `not_applicable`、`uncertain`、`unlocatable` 或降低严重性，并说明需要的人工确认。
